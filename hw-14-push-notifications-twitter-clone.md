# Домашнє завдання: Додавання Push-сповіщень до Twitter Clone

## Мета завдання
Реалізувати відправку та отримання push-сповіщень у вашому застосунку Twitter Clone. Користувачі повинні отримувати сповіщення, коли їхні твіти лайкають, коментують (відповідають), або коли на них підписуються інші користувачі.

## Опис завдання

Використовуючи знання з уроку про push-сповіщення (бібліотека `expo-notifications`, Expo Push Service та Convex), вам потрібно додати функціонал сповіщень у ваш застосунок. 

### Основні кроки для виконання:

#### 1. Налаштування проєкту та дозволів
- Встановіть пакет `expo-notifications`.
- Оновіть `app.config.ts`, додавши плагін `expo-notifications` та необхідні дозволи для Android (зокрема `POST_NOTIFICATIONS`, `VIBRATE`, `RECEIVE_BOOT_COMPLETED` тощо).
- Переконайтеся, що ви використовуєте development build (наприклад, через `npx expo run:android`), оскільки Expo Go не підтримує повноцінно push-сповіщення на нових версіях Android.

#### 2. Оновлення схеми бази даних (Convex)
- Додайте опціональне поле `pushToken` у вашу таблицю користувачів (`users` або `profiles`).

#### 3. Реєстрація Push-токена
- Створіть Convex мутацію (наприклад, `savePushToken`) для збереження токена користувача в БД.
- Створіть React Hook (наприклад, `usePushNotifications`), який:
  - Запитує дозволи на push-сповіщення у користувача.
  - Отримує Expo Push Token для пристрою.
  - Зберігає отриманий токен у базу даних за допомогою раніше створеної мутації.
  - Налаштовує обробники отримання сповіщень (через `Notifications.setNotificationHandler`).
- Підключіть цей хук у кореневому компоненті вашого додатку (наприклад, в `_layout.tsx`), щоб він автоматично відпрацьовував для авторизованих користувачів.

#### 4. Convex Action для відправки сповіщень
- Створіть `internalAction` у Convex (наприклад, `sendPushNotification` у файлі `pushNotifications.ts`), який буде приймати `pushToken`, `title`, `body` та додаткову `data`, і відправляти POST запит на `https://exp.host/--/api/v2/push/send`.

#### 5. Тригери для відправки сповіщень (Мутації)
Оновіть відповідні мутації у вашому бекенді Convex, щоб вони відправляли push-сповіщення через `ctx.scheduler.runAfter` за наступних подій:
1. **Лайк твіта (Like):** Коли користувач лайкає твіт, автор твіта має отримати сповіщення. *Приклад: "Новий лайк ❤️" - "@username вподобав ваш твіт"*.
2. **Коментар до твіта (Reply):** Коли хтось залишає коментар (реплай) на твіт, автор оригінального твіта має отримати сповіщення. *Приклад: "Нова відповідь 💬" - "@username: [текст відповіді]"*.
3. **Підписка (Follow):** Коли користувач підписується на іншого користувача, останній має отримати сповіщення. *Приклад: "Новий підписник 👤" - "@username підписався на вас"*.

#### 6. Налаштування Firebase (для Android)
- Створіть проєкт у Firebase Console.
- Додайте Android застосунок (переконайтеся, що package name точно відповідає вашому конфігу в `app.config.ts`).
- Завантажте `google-services.json` і розмістіть його в корені проєкту та в `android/app/`.
- Оновіть `android/build.gradle` та `android/app/build.gradle` для підключення плагіну `com.google.gms.google-services`.
- Згенеруйте Service Account Key (JSON) у Firebase Console та завантажте його у ваш Expo проєкт за допомогою EAS Credentials (`eas credentials --platform android`) для підтримки FCM V1.

#### 7. Перевірка роботи
- Зробіть новий білд застосунку.
- Авторизуйтеся двома різними акаунтами на двох різних пристроях або симуляторах/емуляторах.
- Зробіть дії (лайк, коментар, підписка) з одного акаунта і переконайтеся, що на інший пристрій успішно приходить push-сповіщення.

### Додаткове завдання (із зірочкою ⭐)
- Реалізуйте навігацію при кліку на сповіщення. Наприклад, якщо користувач клікає на сповіщення про новий лайк або коментар до твіту, застосунок має відкриватися і перенаправляти користувача безпосередньо на екран цього конкретного твіта.

---

## Критерії оцінювання:
1. Застосунок успішно отримує `pushToken` і зберігає його в Convex БД.
2. Expo Push Service інтегрований у Convex Action для надсилання запитів.
3. Сповіщення успішно приходять на пристрій при:
   - Лайку твіта.
   - Коментуванні/відповіді на твіт.
   - Підписці на користувача.
4. Дозволи в Android та Firebase налаштовані коректно, білд проходить без помилок відсутності Google Services чи FCM V1 Credentials.
5. Код чистий, добре структурований і не містить помилок компіляції чи лінтера.
